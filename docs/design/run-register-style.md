# Run Register style vocabulary

The approved V1 presentation is the Fixture Run Register ledger. It records
browser-session fixture evidence; it never depicts live solver execution,
persistence, qualification, or a validated structural prediction.

## Visual vocabulary

- **Masthead:** `RUN REGISTER`, the CMC Pipeline eyebrow, and a red fixture
  stamp make the fixture scope visible before numeric evidence.
- **Ledger:** a dark evidence sidebar sits beside a compact, tabular register.
  The table is for recorded fixture reference runs; a row carries fixture
  identity and revision, declared reference result, and fixture adjudication.
- **Evidence detail:** the most recent row exposes the supplied claim wording,
  reference-solution context, surrogate context when present, and the
  browser-session-only limitation.
- **Tokens:** paper ground, dark ink, red scope marker, and restrained
  uppercase labels distinguish declared metadata from result values.
- **Responsive treatment:** the masthead stacks, the sidebar shortens, and the
  ledger remains horizontally inspectable on narrow viewports.

## Claim-language rules

Use “representative fixture”, “fixture reference run”, “fixture adjudication”,
and “comparison evidence”. Do not claim solver execution, independent physical
validation, qualification, or a design prediction.

## Exclusions

The former paintbox and execution-sequence studies are not approved V1
vocabulary. Their static lifecycle, freshness, cutback, and worker-health
language is deliberately not retained because V1 is a fixture-backed,
in-memory workflow.
